# 默认设备上下文的在线消融对照

## 问题

[离线诊断](engine_phase_profile_zh.md)中，初始化作用域修复后的三轮平均墙钟时间下降 24.3%，
但样例只有 12 个请求，且先跑基线、后跑候选，不能推导在线服务收益。
本实验将同一份最终代码的 CPU 默认设备分派上下文作为唯一消融变量。

## 两种模式

- `legacy_cpu`：引擎创建完成后，在推理工作线程调用 `torch.set_default_device("cpu")`，恢复残留分派模式。
- `scoped`：保留当前限定初始化作用域的实现，不额外设置全局默认设备。

两组都使用当前版本的显式 pinned CPU 输入分配。这里比较的是残留设备上下文的开销，
不是完整历史提交与当前提交的对比。设备设置发生在引擎工厂执行的推理线程，不在 HTTP 主线程。
入口只放在 `benchmarks.serve_device_context`，日常启动仍使用 `nanovllm.serve`。
两组均在服务指标中回传真实模式，压测启动时核对，聚合时拒绝无意混用模式。

## 协议

RTX 4060 8GB，Qwen3-0.6B，eager，PALS/Radix，64 页 KV，每步最多 8 请求。
关闭压缩、Mooncake、追踪、额外页预留和静态驻留上限；指标汇总均为 cached。
每轮 181 请求，每秒 3 请求均匀到达，60 秒到达窗口，待所有请求完成或超时后结束计时。
客户端最多 128 个在途请求，每请求超时 120 秒。到达窗口不等于完整测试耗时。
三轮顺序为 legacy/scoped、scoped/legacy、legacy/scoped，共六次独立服务启动。

交互请求输出上限 64 Token，批处理为 128 Token，temperature=0.1，不是确定性 greedy 测试。
交互 SLO 为 TTFT 1 秒、TPOT 100 ms、E2E 10 秒；批处理为 TTFT 10 秒、TPOT 500 ms、E2E 30 秒。
请求必须满足它配置的全部目标才算 SLO 达标。保留所有失败、超时及实际输出长度。
每轮有独立短提示词预热，不声称已覆盖全部形状/编译路径。

```bash
python -m benchmarks.run_validation device --seed 20260907 \
  --requests 180 --duration 60 --rates 3 --repeats 3 \
  --arrival-process uniform --max-inflight 128 --timeout 120 \
  --output-dir benchmarks/results/device-context-online-20260907
```

结果目录必须为空；使用 `--resume` 时配置与运行时、评测脚本、Shell 启动脚本哈希必须匹配。
原始逐请求数据、服务日志、状态、配置清单和逐轮结果全部保存。
只终止本套件创建的进程组，不占用或结束日常服务；端口为 8031，NCCL 为 2333。

## 结论边界

这是一个负载档位、三轮的小规模在线压力消融，不是长期稳定性、峰值容量或多模型评估。
每类约 90 个样本，尾部百分位尤其不宜推广；均值及三轮置信区间应共同报告。
PALS 的批次与排队会随真实执行时间改变，这种对照衡量服务效果，不等于固定 Kernel 计划的加速。
历史 432 题质量测试和之前 9,012 请求的持续压测不是本轮新增测试，不合并统计。

## 2026-09-07 结果

六轮全部完成：1,086/1,086 请求成功，0 失败，每轮 17,344 输出 Token，总计 104,064 Token。
六轮请求指纹均为 `1a947add1cfbdfec`，采集结束后的源码/启动脚本哈希与 manifest 完全匹配。
测试期间没有修改被测运行时代码，也没有删除或重跑替换异常轮次。

下表是三轮指标均值；P95 列先逐轮计算再取均值，不是合并样本后重算的 P95。
`+/-` 为三轮均值的 95% Student-t 区间半宽，而不是单个请求的延迟范围。

| 指标 | legacy_cpu | scoped | 均值变化 |
| --- | ---: | ---: | ---: |
| 输出吞吐 Token/s | 183.49 +/- 7.47 | 222.28 +/- 24.20 | +21.1% |
| 交互 E2E P95，秒 | 13.33 +/- 6.40 | 2.82 +/- 1.01 | -78.8% |
| 批处理 E2E P95，秒 | 34.26 +/- 4.67 | 17.86 +/- 5.25 | -47.9% |
| SLO Goodput，请求/秒 | 0.802 +/- 0.630 | 2.094 +/- 0.693 | +161.0% |
| 交互 SLO 达标率 | 56.8% | 98.2% | +41.4 个百分点 |

交互 TTFT P95 均值从 10.750 秒降至 0.405 秒，逐轮分别为：

| 轮次 | legacy_cpu TTFT P95，ms | scoped TTFT P95，ms |
| --- | ---: | ---: |
| 1 | 12215.02 | 290.02 |
| 2 | 7801.56 | 274.70 |
| 3 | 12232.25 | 651.49 |

三组输出吞吐与交互延迟的改善方向一致。此处证明的是该负载下设备分派上下文消融的服务效果，
不能归功于 Radix、Mooncake 或 KV 压缩，也不是与未经修改的上游 nano-vLLM 的直接比较。
调度本身未改动，但执行加快会改变排队与批次，从而使尾延迟下降幅度大于吞吐提升幅度。
这不代表每个 Kernel 或每次模型执行都加速了 78.8%。

尤其需要保留以下限制：候选平均完成速率约 2.32 请求/秒，仍低于输入的 3 请求/秒，
不能宣称系统可以长期稳定承载 3 请求/秒。98.2% 仅是这批交互样本的达标率，不是服务承诺。
没有测多档负载、其他模型、CUDA Graph 模式或多机；GPU Kernel 时间线缺失的问题也仍未解决。

完整逐轮与置信区间见 `benchmarks/results/device-context-online-20260907/device-3-comparison.md`。
本轮新增回归覆盖工厂所在路径的模式设置、指标标签、交替顺序及错误混组拒绝。
当前全量回归 208 项通过。

## 简历使用

可作为补充工程成果，替换一条泛泛的“完善评测”描述，而不是继续增加技术名词：

> 定位推理热路径中的全局默认设备分派开销，将设备设置限定于模型初始化并显式分配 CPU pinned 输入；
> 在 RTX 4060、Qwen3-0.6B 的 3 请求/秒短时在线负载下，完成三轮交替消融、共 1,086 请求，
> 平均输出吞吐提升 21.1%，交互 E2E P95 均值降低 78.8%，全部请求成功。

面试时应同时说明：这是同代码设备上下文消融，不是与完整上游仓库比较；
每轮到达窗口 60 秒，不代表长期 SLO 保证，结果仍需要更多负载与重复验证。
