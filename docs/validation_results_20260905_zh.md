# 本轮优化与实机验证结果

本轮完成同预算质量评测、持续请求压测，以及 Query-Aware 零匹配时保留预算不足的修复。
环境为 WSL、RTX 4060 8GB、Qwen3-0.6B；没有使用 Mooncake/RDMA 加速。

## 质量：216 题 x 3 策略

覆盖 3 种输入文本长度、3 个证据位置、4 类任务，每组合 6 个随机答案。
两种压缩策略均保留 5 页，实际累计 KV Token 丢弃比例均为 58.3%。

| 策略 | 正确题数 | 准确率 |
| --- | ---: | ---: |
| 不压缩 | 162/216 | 75.0% |
| 固定 Sink + Recent | 58/216 | 26.9% |
| Query-Aware | 152/216 | 70.4% |

Query-Aware 比相同预算的固定窗口高 43.5 个百分点，比不压缩低 4.6 个百分点。
逐题对照中有 14 题由正确变错误、4 题由错误变正确。问题改写类仍是薄弱项。
这些是合成任务结果，采样温度为 0.1，不能宣称通用质量无损。

[原始质量报告与任务分项](../benchmarks/results/validation-20260905-quality-v2/quality-comparison.md)

## 性能：601 请求 x 2 策略

两组使用完全相同的轨迹：每秒 2 个请求，300 个 Batch、301 个 Interactive，
计划到达时长 300.5 秒，均完成 601 个请求、输出 57664 Token，无失败请求。
使用 64 页 KV 池、8 个并发执行槽位、PALS + Radix。
压缩阈值为 1.0，用于主动触发策略对照，不是线上推荐默认值。

| 指标 | 不压缩 | Query-Aware | 变化 |
| --- | ---: | ---: | ---: |
| 请求吞吐 | 1.910 req/s | 1.961 req/s | +2.7% |
| 输出吞吐 | 183.3 token/s | 188.2 token/s | +2.7% |
| 交互服务端 E2E P95 | 3323.5 ms | 2893.8 ms | -12.9% |
| 交互客户端 E2E P95 | 3751.2 ms | 2926.3 ms | -22.0% |
| Batch 服务端 E2E P95 | 15043.2 ms | 13278.5 ms | -11.7% |
| 交互服务端 TTFT P95 | 357.3 ms | 224.3 ms | -37.2% |
| 交互服务端 TTFT P50 | 81.3 ms | 107.6 ms | +32.4% |
| 抢占次数 | 4 | 0 | -4 |
| 重计算 Token | 4788 | 0 | -4788 |
| GPU 采样显存峰值 | 4631 MiB | 4779 MiB | +3.2% |

Query-Aware 累计触发 500 次压缩、释放 500 页、丢弃 128000 KV Token。
释放 KV 页不等于归还 CUDA 分配器的显存，因此不能把 Token 丢弃比例写成显存峰值降幅。
当前实验观察到更少抢占，但尚未用 profiler 分离调度、压缩与重计算的耗时贡献。

两组吞吐接近设定的到达率，本实验不用于宣称最大服务容量。它也没有复现历史小负载的
70.2% 吞吐提升。仅重复 1 轮，不能报告稳定提升或有置信度的性能改善；每类约 300
个请求，P99 仍缺乏足够尾部样本。SLO 交互达成率从 300/301 变为 301/301，
只有一个请求的差异，不作为独立卖点。

## 工程验证

- 全量单元/集成测试：136 passed。
- CI 静态检查：Ruff F 规则通过。
- 确定性调度与分层缓存模拟检查通过；模拟结果不计入上述 GPU 性能数字。
- 实验进程已退出，8031 服务端口及 2333 NCCL 端口均已释放。
- 首次质量实验因端口重用检查失败而中断，保留并标为不完整；上表使用完整重跑的 v2 数据。

## 尚待完成

同一压力点重复至少 3 轮，补充多个到达率、多个随机轨迹、正常自动页池容量、
更长输出和真实文本任务。质量测试需要留出独立种子作为验证集，避免围绕当前题目调参。
进一步改进问题改写时的页相关性估计，并量化计算成本与质量收益。
