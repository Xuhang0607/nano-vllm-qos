# 独立样本与重复实机验证

## 固定配置

Qwen3-0.6B BF16、RTX 4060 8GB、WSL，PALS + Radix，64 页 KV 池，
每页 256 Token，每步最多调度 8 个序列。两种压缩策略均保留 5 页。
压缩触发阈值为 1.0，用于主动触发对照，不是生产推荐配置。

## 两组独立质量样本

固定算法与参数，使用种子 20260905、20260906 分别生成 216 题。
每组覆盖 3 种文本长度、3 个证据位置、4 类任务。合计每策略 432 题。

| 策略 | 第一组 | 独立第二组 | 合计正确 | 合计准确率 |
| --- | ---: | ---: | ---: | ---: |
| 不压缩 | 162/216 | 158/216 | 320/432 | 74.1% |
| 固定窗口 | 58/216 | 59/216 | 117/432 | 27.1% |
| Query-Aware | 152/216 | 153/216 | 305/432 | 70.6% |

两种压缩策略累计 KV Token 丢弃比例均为 58.3%。Query-Aware 相比同预算固定窗口
高约 43.5 个百分点，相比不压缩低约 3.5 个百分点。采样温度为 0.1，存在运行随机性。
这是合成检索任务结果，不代表长文摘要、真实问答或通用质量无损。

## 重复性能验证

已完成固定间隔 2、3 req/s 两档实验，每档不压缩与 Query-Aware 各重复三轮，
交替运行先后顺序。每轮分别为 601、901 个请求，共 12 轮、9012 个请求。
两种策略均使用修复后的异步事件通知服务，客户端并发上限统一设为 512。
成功 8797 个、失败 215 个：200 个读取等阶段超时、15 个连接超时。无客户端并发上限
拒绝，最大发送偏差约 38.81 ms。失败轮次全部保留，未以重跑后的成功轮次替换。
`validation-20260905-repeated/status.json` 已标记 complete；这表示实验结束，不表示零失败。

以新种子固定请求轨迹；先预热再计时。记录完成与失败请求、实际输出长度、
客户端发送延迟、服务端 TTFT/TPOT/E2E、KV 重计算和 GPU 采样指标。
原始配置和源码摘要保存在 `manifest.json`。

### 统计口径与限制

- 交互 SLO：引擎 TTFT <= 1000 ms、TPOT <= 100 ms、E2E <= 10000 ms，全部满足才达标。
- Batch SLO：引擎 TTFT <= 10000 ms、TPOT <= 500 ms、E2E <= 30000 ms。
- SLO 是本实验事先设定的目标，不是行业标准。失败请求计入 offered SLO 分母。
- HTTP 使用非流式请求；TTFT/TPOT 为引擎埋点，客户端 E2E 另行测量。
- 延迟分位数仅统计成功请求，必须同时查看失败率，不能把超时隐藏在分位数之外。
- 聚合报告的请求级 `kv.*` 指标来自返回结果的请求，不包含超时后无法回传的计数；
  服务端全局计数差值另见 `metric_deltas`，两种口径不可混用。
- 吞吐分母包含 300 秒到达窗口及请求排空时间，不以到达速率冒充完成吞吐。
- 300 秒 socket timeout 不是严格的端到端墙钟截止时间；连接和读取阶段可能导致更长等待。
- 单类每轮不足 1000 次完成请求，P99 尾部样本不足；三轮置信区间也只是描述性参考。
- GPU 总显存采样不是进程独占显存，当前数据不证明峰值显存按 KV 丢弃比例下降。
- Mooncake 在本轮对照中关闭，不能把结果用于证明远端 KV 或 RDMA 加速。

## 服务层故障与修复

首次扩大压测时，旧服务的客户端 E2E 中位数约 61 秒，明显高于引擎记录的时间，
同时触发客户端并发限制。旧实现通过 `asyncio.to_thread(queue.get)` 等待每个请求，
等待中的请求可能占满默认线程池，使已有结果也无法及时消费。

改为线程安全的队列加事件循环通知，异步等待不占用线程；保留同步 `get` 接口，
并处理取消、超时、跨线程唤醒和事件循环关闭。非流式请求只在结束时解码一次，
省去逐 Token 的累计文本解码和不必要的中间事件。

回归测试在默认执行器已占满的条件下创建 128 个等待者，验证最后一个就绪请求仍能
完成；另验证取消不吞事件、非流式长等待、SSE 格式以及仅一次解码。
全量测试共 142 项通过，静态检查通过。

中止的性能数据仅用于故障诊断，不和修复后的重复实验混合统计。

## 收尾验证与结论

- 全量回归：`python -m pytest -q`，142 passed，18.59 秒。
- 静态检查：`python -m ruff check --select F nanovllm benchmarks tests scripts`，通过。
- 实验清单中的 44 个 Python 文件 SHA-256 均与完成时源码相符。
- 实验进程正常结束，8031 与 NCCL 2333 端口已释放。

可以量化写入简历的是同预算合成检索质量改进、持续压测覆盖和回归覆盖；本轮不能宣称
稳定吞吐提升、通用无损压缩或生产级服务容量。下一阶段应以真实任务、正常自动页池、
多请求轨迹和 CPU/GPU 时间线定位为依据，再决定是否继续优化选页与调度。
